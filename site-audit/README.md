# سلامت‌سنجی سایت حسابیار

اسکریپت مستقل و بدون‌وابستگی که وب‌سایت دیپلوی‌شده (فرانت + بک‌اند) رو خودکار تست می‌کنه:
دسترس‌پذیری صفحات، امنیت پایه، جریان کامل کاربر (ثبت‌نام تا فاکتور و پرداخت)، ایزوله‌سازی
چندمستأجری، rate limiting، و (اختیاری) پنل سوپرادمین.

## اجرا

```bash
cd site-audit
cp .env.example .env
# مقدارهای .env رو با آدرس واقعی سایت دیپلوی‌شده پر کن
node healthcheck.mjs
```

نیازی به `npm install` نیست — فقط از `fetch` داخلی Node (نسخه ۱۸ به بالا) استفاده می‌کنه.

## چی رو باید توی `.env` پر کنی؟

| متغیر | توضیح |
|---|---|
| `API_BASE_URL` | آدرس بک‌اند دیپلوی‌شده (Render یا هرجا) |
| `FRONTEND_BASE_URL` | آدرس فرانت دیپلوی‌شده |
| `ADMIN_HTML_PATH` | معمولاً `/admin.html`، تغییر نده مگه مسیرش رو عوض کرده باشی |
| `TEST_USER_EMAIL` / `TEST_USER_PASSWORD` | اختیاری — یه شرکت **تستی** جدا (نه مشتری واقعی)؛ اگه خالی بمونه، اسکریپت خودش یه شرکت تستی می‌سازه و در پایان پاکش می‌کنه |
| `SUPERADMIN_EMAIL` / `SUPERADMIN_PASSWORD` / `ADMIN_ROUTE_SECRET` | اختیاری — اگه پر نباشه فقط تست‌های سوپرادمین رد (skip) می‌شن، فیل نمی‌شن |
| `KEEP_TEST_DATA` | اگه `true` باشه دیتای تستی که ساخته رو پاک نمی‌کنه (برای بررسی دستی) |
| `REQUEST_DELAY_MS` | فاصله بین درخواست‌ها؛ اگه سرور دیپلوی‌شده rate limit سخت‌گیرانه داره، بزرگ‌ترش کن |

## ⚠️ نکته‌ی امنیتی مهم

- **این اسکریپت رو با کاربر/شرکت واقعی مشتری اجرا نکن.** یا `TEST_USER_EMAIL` رو خالی بذار
  (خودش شرکت تستی می‌سازه و پاک می‌کنه)، یا اگه پر می‌کنی حتماً یه شرکت تستی جدا باشه.
- فایل `.env` رو هیچ‌جای عمومی (گیت‌هاب و غیره) آپلود نکن — رمز واقعی توشه.
- بخش تست rate limit عمداً ۲۵ درخواست ناموفق پشت‌سرهم به `/api/auth/login` می‌زنه با یه
  ایمیل ساختگی (نه ایمیل واقعی)، پس حساب هیچ کاربر واقعی‌ای رو قفل نمی‌کنه.

## خروجی

- روی کنسول همون لحظه پاس/فیل/هشدار هر آیتم رو می‌بینی
- یه فایل کامل توی `reports/report-<تاریخ>.md` ذخیره می‌شه

## بعد از اجرا چی برام بفرستی؟

**همون فایل `reports/report-....md` رو مستقیم برام بفرست** — کامل‌ترین و دقیق‌ترینه.
اگه نمی‌تونی فایل بفرستی، حداقل این‌ها رو کپی کن:

1. خط خلاصه (`📊 خلاصه: X موفق، Y ناموفق، ...`)
2. **هر خط ❌ (ناموفق)** به‌طور کامل، با پیام جزئیاتش
3. **هر خط ⚠️ (هشدار)** به‌طور کامل
4. اگه بخش «رفرش مستقیم روی یک مسیر داخلی» ⚠️ داد، بگو هاست فرانتت کجاست (Vercel، Netlify،
   Render Static، سرور خودت و ...) — چون راه‌حلش بسته به هاست فرق می‌کنه
5. اگه ممکنه، خروجی کامل ترمینال رو هم بفرستی بهتره (حتی خطوط ✅، برای اطمینان از این‌که
   واقعاً همه‌چی اجرا شده نه اینکه یه‌جا کرش کرده)

## این اسکریپت چی رو **بررسی نمی‌کنه** (باید دستی/با چک‌لیست جدا تست بشه)

- ظاهر بصری، رنگ، جابه‌جایی drag-and-drop کارت‌ها
- محتوای واقعی PDF فاکتور (فقط چک نمی‌شه که endpoint جواب می‌ده، نه که PDF درست رندر شده)
- حالت آفلاین (نیاز به شبیه‌سازی قطع اینترنت مرورگر داره)
- برای این موارد از `QA/MANUAL_TEST_CHECKLIST.md` (توی ریشه‌ی پروژه‌ی اصلی) استفاده کن —
  این دو مکمل همن، نه جایگزین.

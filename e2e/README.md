# تست e2e حسابیار (Playwright)

تست‌های end-to-end سبک برای مسیرهای بحرانی برنامه — با مرورگر واقعی، در برابر
backend و frontend واقعی (نه mock)، روی یک دیتابیس SQLite جدا و یک‌بارمصرف
(`hesabyar-backend/data/e2e.sqlite`) که با هر اجرا از نو ساخته می‌شه.

## چرا جدا از تست‌های vitest؟

- `hesabyar-frontend/tests` و `hesabyar-backend/tests` (vitest) → تست واحد/کامپوننت،
  سریع، بدون مرورگر واقعی، برای منطق و رفتار هر بخش به‌تنهایی.
- این پوشه (`e2e/`) → فقط چند مسیر بحرانی سرتاسری، با مرورگر واقعی، برای اطمینان
  از اینکه فرانت و بک‌اند واقعاً با هم کار می‌کنن (نه اینکه هرکدوم جدا تست پاس
  کنن ولی سیم‌کشی بینشون خراب باشه).

## اجرا

```bash
cd e2e
npm install
npx playwright install --with-deps chromium   # فقط بار اول (باینری مرورگر ~۳۰۰ مگابایت)
npm test
```

`playwright.config.js` خودش backend (پورت ۴۰۰۰) و frontend (پورت ۵۱۷۳) رو با
یک `.env` مخصوص تست بالا میاره — نیازی به اجرای دستی `npm run dev` جدا نیست
(مگر اینکه بخوای در حالت توسعه، سرورهای از قبل بالا رو استفاده کنه که خودش این
کارو می‌کنه چون `reuseExistingServer: !CI`).

برای دیدن مرورگر حین اجرا: `npm run test:headed`
برای حالت تعاملی/دیباگ: `npm run test:ui`

## ⚠️ وضعیت فعلی

این تست‌ها در محیطی نوشته شدن که دانلود باینری Chromium (از `cdn.playwright.dev`)
در sandbox مسدود بود، پس هنوز **یک‌بار هم با مرورگر واقعی اجرا نشدن**. سلکتورها
از روی خوندن دقیق کد صفحات (placeholder، متن دکمه، مسیر route) نوشته شدن، اما
قبل از تکیه‌کردن روی این تست در CI، حتماً یک‌بار محلی اجرا کن — اگه سلکتوری جا
افتاد یا عوض شده بود، پیام خطای Playwright دقیقاً نشون می‌ده کدوم `expect`/`click`
شکست خورده.

## افزودن تست جدید

فایل‌های `.spec.js` جدید رو داخل `tests/` بذار. چون همه از یک دیتابیس مشترک
استفاده می‌کنن (`workers: 1` در کانفیگ)، هر تست باید با ایمیل/نام یکتا
(مثلاً `Date.now()` مثل تست فعلی) کار کنه تا با تست‌های دیگه تداخل نکنه.

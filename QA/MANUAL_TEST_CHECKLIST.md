# چک‌لیست تست دستی حسابیار

این فایل رو مرحله‌به‌مرحله طی کن. جلوی هر مورد که تست کردی ✅ بذار، جلوی هر موردی که مشکل داشت ❌ بذار و توضیح بده چی دیدی. هرچی پیدا کردی رو برام بفرست تا فیکس کنم.

## قبل از شروع

```bash
cd hesabyar-backend && npm install && cp .env.example .env
npm run seed        # یه شرکت تستی + owner + سوپرادمین می‌سازه، ایمیل/رمزها رو یادداشت کن
npm run dev         # پورت 4000

cd hesabyar-frontend && npm install && npm run dev   # پورت 5173 (پنل شرکت) + /admin.html (سوپرادمین)
```

- [ ] خروج از حساب (دکمه‌ی logout در بالای صفحه) → باید به `/login` برگردونه

## بخش ۲ — نقش Owner (مالک شرکت) — همه‌ی صفحات

### داشبورد (`/`)
- [ ] بعد از ورود اول‌بار (بدون دیتا)، باید بنر زرد «داده‌ی نمونه» رو ببینی
- [ ] دکمه‌ی «شخصی‌سازی چیدمان» بالای صفحه رو بزن
- [ ] یکی از باکس‌ها رو با موس بکش و جابجا کن → باید جاش عوض بشه
- [ ] یکی از باکس‌ها رو با دکمه‌ی چشم مخفی کن → باید ناپدید بشه
- [ ] دکمه‌ی «افزودن باکس» رو بزن → باکس مخفی‌شده باید توی لیست باشه، دوباره اضافه‌اش کن
- [ ] دکمه‌ی «بازگردانی پیش‌فرض» رو بزن → باید به چیدمان اول برگرده
- [ ] صفحه رو رفرش کن (F5) → چیدمانی که ذخیره کردی باید باقی مونده باشه (نه پاک بشه)

### فاکتورها (`/invoices`)
- [ ] دکمه‌ی «فاکتور جدید» → فرم باز بشه
- [ ] یه مشتری انتخاب کن (اگه مشتری نداری، اول یکی از تب مشتریان بساز)
- [ ] تاریخ صدور و سررسید رو با انتخاب‌گر شمسی (روز/ماه/سال) تنظیم کن
- [ ] چند ردیف قلم اضافه کن (شرح/تعداد/قیمت) → جمع باید خودکار محاسبه بشه
- [ ] تخفیف و درصد مالیات رو تغییر بده → مبلغ نهایی باید آپدیت بشه
- [ ] «ذخیره پیش‌نویس» بزن → فاکتور با وضعیت پیش‌نویس ساخته بشه
- [ ] یه فاکتور دیگه بساز و «صدور فاکتور» بزن → وضعیت باید «در انتظار پرداخت» باشه
- [ ] روی آیکون چشم (مشاهده) یه فاکتور کلیک کن → جزئیات کامل، اقلام، و وضعیت پرداخت (مانده/پرداخت‌شده) رو نشون بده
- [ ] از همون پنجره‌ی جزئیات، دکمه‌ی «دانلود PDF» رو بزن → یه فایل PDF واقعی باید دانلود بشه، بازش کن و چک کن فارسی/اطلاعات درست نمایش داده شده
- [ ] از همون پنجره، دکمه‌ی «ویرایش» رو بزن → فرم باید با اطلاعات فاکتور پر شده باشه
- [ ] یه فیلد رو عوض کن و «ذخیره تغییرات» بزن → تغییر باید اعمال بشه
- [ ] آیکون ویرایش (مداد) توی جدول رو مستقیم بزن → همون فرم ویرایش باید باز بشه
- [ ] یه فاکتور رو حذف کن → باید تاییدیه بخواد و بعد حذف بشه
- [ ] فیلتر وضعیت (پیش‌نویس/در انتظار/پرداخت‌شده/سررسیدگذشته) رو تست کن
- [ ] جست‌وجو با شماره فاکتور یا نام مشتری رو تست کن
- [ ] کارت‌های آماری بالای صفحه رو با موس جابجا/مخفی کن (مثل داشبورد)

### دریافتی‌ها (`/receipts`) و پرداختی‌ها (`/payments`)
- [ ] یه دریافتی جدید ثبت کن (نقدی) — تاریخ با انتخاب‌گر شمسی
- [ ] یه دریافتی چکی ثبت کن — باید فیلدهای شماره چک/تاریخ چک/بانک ظاهر بشن
- [ ] یه دریافتی رو به یه فاکتور خاص وصل کن (فیلد انتخاب فاکتور)
- [ ] برو به همون فاکتور در تب فاکتورها → باید مبلغ «پرداخت‌شده» و «مانده» درست آپدیت شده باشه
- [ ] همین کار رو برای پرداختی‌ها هم تکرار کن
- [ ] یه پرداخت به یه شریک خاص با یه کارت بانکی خاص وصل کن (PartnerAccountSelect)

### هزینه‌ها (`/expenses`)
- [ ] یه هزینه‌ی جدید ثبت کن با انتخاب شریک پرداخت‌کننده و دسته‌بندی
- [ ] فیلتر بر اساس دسته‌بندی رو تست کن
- [ ] کارت «بیشترین دسته» باید واقعاً دسته‌ای که بیشترین مبلغ رو داره نشون بده

### مشتریان (`/clients`)
- [ ] مشتری جدید (حقیقی و حقوقی) بساز
- [ ] ویرایش و حذف یه مشتری
- [ ] جست‌وجو با نام/تلفن/ایمیل

### محصولات (`/products`)
- [ ] محصول/خدمت جدید بساز، قیمت و موجودی تنظیم کن
- [ ] یه محصول با موجودی کمتر از حداقل بساز → باید توی کارت «موجودی کم» بشمارتش

### کارمندان و پرسنل (`/employees`)
- [ ] کارمند جدید بساز
- [ ] کارت لینک «شرکا و سهام‌داران» بالای صفحه رو ببین → کلیک کن، باید به `/partners` ببره

### شرکا و سهام‌داران (`/partners`) — صفحه‌ی مستقل جدید
- [ ] شریک جدید با درصد سهام، سرمایه‌ی اولیه و یه کارت بانکی بساز
- [ ] کارت‌های آماری بالا (تعداد شرکا، کل حقوق صاحبان سهام، سهام ثبت‌شده، سرمایه‌ی اولیه) رو با دیتای واقعی مقایسه کن
- [ ] اگه مجموع سهام شرکا ۱۰۰٪ نشه، کارت «سهام ثبت‌شده» باید قرمز/هشدار نشون بده
- [ ] نمودار دایره‌ای ترکیب مالکیت رو بررسی کن (باید با درصدها هم‌خونی داشته باشه)
- [ ] روی یه شریک کلیک کن → صفحه‌ی جزئیات باز بشه، موجودی حساب و تاریخچه‌ی دفتر (اول خالی) رو ببین
- [ ] «ثبت آورده» بزن، یه مبلغ ثبت کن → موجودی باید بلافاصله بالا بره و ردیف جدید توی تاریخچه بیاد
- [ ] «ثبت برداشت» بزن، مبلغی بیشتر از موجودی فعلی بده → باید با خطا رد بشه
- [ ] یه ردیف دفتر (غیر از تقسیم سود) رو حذف کن → موجودی باید برگرده
- [ ] از صفحه‌ی اصلی شرکا، «تقسیم سود» رو بزن، مبلغ کل رو وارد کن → پیش‌نمایش مبلغ هر شریک به‌نسبت سهامش رو بررسی کن، ثبت کن
- [ ] بعد از تقسیم سود، توی تاریخچه‌ی هر شریک یه ردیف «سهم سود» جدید باید دیده بشه؛ سعی کن حذفش کنی → باید پیام بده که بخشی از یه دسته‌ی گروهیه
- [ ] یه شریک رو ویرایش کن (تغییر سمت/کارت بانکی) → ذخیره بشه
- [ ] یه شریک بدون تراکنش حذف کن → از لیست بره

### حساب‌های بانکی (`/banking`)
- [ ] حساب بانکی جدید بساز
- [ ] کارت‌های «دریافتی‌ها»/«پرداختی‌ها» رو با اعداد واقعی صفحه‌ی پرداختی‌ها مقایسه کن، باید هم‌خونی داشته باشه (چون تجمعیه)

### گزارشات (`/reports`)
- [ ] تب «خلاصه کلی» — کارت‌ها و نمودارها رو با موس جابجا کن (شخصی‌سازی)
- [ ] نمودار ماهانه رو چک کن: اگه فاکتورهای جدید (با تاریخ شمسی درست) ثبت کردی، باید دیگه برچسب «نمونه» نداشته باشه
- [ ] تب «جریان نقدی» رو ببین
- [ ] تب «شرکا» و «مشتریان» (برترین‌ها) رو ببین
- [ ] تب «مالیات» — باید صریحاً بگه این فقط نمونه‌ست

### یکپارچه‌سازی هلو (`/holo`)
- [ ] فرم اتصال (host/port/database/user/password) رو ببین
- [ ] بدون اطلاعات واقعی، «تست اتصال» بزن → باید خطای منطقی بده (نه crash)
- [ ] (اگه SQL Server واقعی در دسترس داری) یه تست واقعی اتصال/Import انجام بده

### تنظیمات (`/settings`)
- [ ] تب «اطلاعات شرکت» — ویرایش نام/تلفن/آدرس شرکت، ذخیره، رفرش کن ببین موند
- [ ] تب «پروفایل من» — ویرایش نام، ذخیره
- [ ] تب «کاربران» — یه کاربر جدید دعوت کن (نقش کارمند/مدیر) → رمز موقت باید نشون داده بشه
- [ ] با همون رمز موقت (توی یه تب Incognito) وارد شو، چک کن نقشش محدوده
- [ ] تب «امنیت» — رمز عبورت رو عوض کن، خروج بزن، با رمز جدید وارد شو
- [ ] تب «ظاهر و زبان» — هر ۵ تم رو امتحان کن، مقیاس فونت رو عوض کن (کوچک تا خیلی بزرگ)، زبان رو به انگلیسی عوض کن و برگردون
- [ ] تب «اعلان‌ها» و «دسترسی‌ها» — ببین بنر «فقط محلی» درست نشون داده می‌شه

### نظارت مالک (`/oversight`)
- [ ] تب «نمای کلی» — لیست کاربران زیرمجموعه
- [ ] تب «لاگ فعالیت‌ها» — باید فعالیت‌های واقعی (ساخت فاکتور، ورود و...) که انجام دادی رو ببینی
- [ ] فیلتر بر اساس کاربر/نوع عملیات
- [ ] تب «مدیریت دسترسی‌ها» — کاربر زیرمجموعه رو حذف کن

### زنگ اعلان و جست‌وجو (بالای هر صفحه)
- [ ] یه فاکتور با سررسید ۲ روز دیگه بساز → باید توی زنگ اعلان بالای صفحه ظاهر بشه (رنگ نارنجی)
- [ ] یه فاکتور با سررسید گذشته بساز → باید قرمز باشه
- [ ] روی یه اعلان کلیک کن → باید به صفحه‌ی مربوطه ببره
- [ ] جست‌وجوی بالای صفحه (یا Ctrl+K) رو بزن، اسم یه مشتری/فاکتور/محصول رو تایپ کن → نتایج گروه‌بندی‌شده باید بیاد

## بخش ۳ — نقش کارمند/مدیر (Employee/Admin)

با کاربری که از تب «کاربران» دعوت کردی وارد شو و این‌ها رو چک کن:

- [ ] آیا به صفحه‌ی «نظارت مالک» دسترسی داره؟ (نباید داشته باشه، یا باید محدود باشه)
- [ ] آیا می‌تونه تنظیمات شرکت (اطلاعات کلی) رو عوض کنه؟ (باید محدودتر از owner باشه)
- [ ] آیا می‌تونه فاکتور/مشتری/محصول بسازه؟ (باید بتونه)
- [ ] آیا می‌تونه کاربر دیگه‌ای دعوت/حذف کنه؟ (بسته به نقش admin/employee باید فرق کنه)
- [ ] آیا صفحه‌ی «شرکا» (`/partners`) توی منو براش دیده می‌شه، حتی وقتی پرمیشن ماژول `partners`ش خاموشه؟ (منوی فرانت فعلاً بر اساس پرمیشن فیلتر نمی‌شه — این محدودیت شناخته‌شده‌ست، مخصوص partners نیست، هر صفحه رو شامل می‌شه؛ فقط تایید کن که بک‌اند خودش با ۴۰۳ درست جلوش رو می‌گیره حتی اگه لینک قابل‌کلیکه)

⚠️ **این بخش مهمه چون مشخص نیست چقدر RBAC واقعی پیاده‌سازی شده — لطفاً هرچی که کارمند نباید بتونه انجام بده ولی تونست، برام بنویس.**

## بخش ۴ — پنل سوپرادمین (`/admin.html`)

- [ ] ورود با ایمیل/رمز سوپرادمین (از seed) → باید مرحله‌ی OTP بخواد
- [ ] کد OTP رو از لاگ کنسول سرور (ترمینالی که `npm run dev` توش اجراست) پیدا کن و وارد کن
- [ ] بعد از ۵ رمز اشتباه در مرحله‌ی اول → قفل حساب

### داشبورد سوپرادمین
- [ ] آمار کلی (تعداد شرکت، کاربر، درآمد) رو ببین
- [ ] نمودار «رشد پلتفرم» رو ببین (باید واقعی باشه، بدون برچسب نمونه)
- [ ] دکمه‌ی «بکاپ دستی دیتابیس» رو بزن → باید پیام موفقیت بده

### شرکت‌ها
- [ ] لیست همه‌ی شرکت‌های ثبت‌شده (شرکت تستی خودت + شرکت‌های ثبت‌نامی)
- [ ] وضعیت یه شرکت رو به «تعلیق» تغییر بده
- [ ] با owner همون شرکت (تب دیگه) لاگین کن → باید پیام «حساب شرکت غیرفعال شده» بگیره
- [ ] دوباره وضعیتش رو «فعال» کن

### صورتحساب‌ها
- [ ] تب «نمای کلی» و «پلن‌ها» — تعداد شرکت به تفکیک پلن
- [ ] تب «درآمد شرکت‌ها» — دکمه‌ی «تغییر پلن» رو تست کن

### کاربران (cross-company)
- [ ] لیست همه‌ی کاربران همه‌ی شرکت‌ها
- [ ] یه کاربر رو تعلیق کن
- [ ] رمز یه کاربر رو ریست کن → رمز موقت باید نشون داده بشه

## بخش ۵ — حالت آفلاین

- [ ] در حال استفاده از برنامه، اینترنت/سرور بک‌اند رو قطع کن (سرور رو با Ctrl+C در ترمینال متوقف کن)
- [ ] سعی کن یه مشتری یا فاکتور جدید بسازی → باید بگه «در صف ارسال (آفلاین)» و توی لیست محلی نشون داده بشه
- [ ] سرور رو دوباره روشن کن (`npm run dev`) → باید خودکار sync بشه و وضعیت واقعی بگیره

## بخش ۶ — چیزهایی که از قبل مشخصه محدودیت دارن (این‌ها رو گزارش نده، می‌دونیم)
- موتور محاسبه‌ی مالیات (فقط نمونه‌ست)
- یکپارچه‌سازی واقعی هلو (نیاز به SQL Server واقعی)
- کدینگ حسابداری کامل (اصلاً ساخته نشده)
- سرویس ایمیل واقعی (رمزهای موقت/OTP فقط لاگ می‌شن، ایمیل نمی‌شن)
- صفحه‌ی فراموشی رمز ممکنه هنوز وایر نشده باشه

## گزارش نتیجه

برای هر مورد ❌، لطفاً این‌ها رو بنویس:
